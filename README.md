# VTA Namelist (Next.js + Supabase + Vercel)

## ติดตั้ง
1. สร้างโปรเจกต์ Supabase (เลือก region Singapore) แล้วเปิด SQL Editor
2. รัน `select vault.create_secret('<สุ่มยาว 32+ ตัวอักษร>','pii_key');` (เก็บ key สำรองไว้ที่ปลอดภัย ถ้าหายจะถอดรหัสไม่ได้)
3. รัน `001_schema.sql`, `002_admin.sql`, `003_import.sql`, `004_bulk_move.sql`, `005_files.sql`, `006_audit_labels.sql`, `007_service_branches.sql`, `008_resignation.sql`, `009_blacklist.sql`, `010_dashboard.sql`, `011_search.sql` (ตามลำดับ; 005 สร้าง bucket `namelist-files` แบบ private ให้อัตโนมัติ)
4. Authentication > Providers: ปิด "Allow new users to sign up" แล้วสร้างผู้ใช้เองที่ Authentication > Users
5. ตั้ง Admin คนแรก: `update profiles set role='admin' where id='<uuid>';`
6. ใส่ `SUPABASE_SERVICE_ROLE_KEY` ใน Vercel (Production เท่านั้น ไม่ใส่ prefix NEXT_PUBLIC) สำหรับการเชิญผู้ใช้ และตั้งค่า SMTP ที่ Supabase > Auth > SMTP เพื่อส่งอีเมลเชิญ
7. Push โค้ดขึ้น GitHub > Import เข้า Vercel > ใส่ env ตาม `.env.example` (Vercel region: Singapore)
8. เปิด MFA สำหรับ Admin ทุกคน และเปิด Daily Backup (Supabase Pro)

## กำหนดสิทธิ์ผ่านหน้า /admin (Admin คนแรกต้องตั้งด้วย SQL ข้างบน)
ตัวอย่าง SQL เทียบเท่า:
```sql
update profiles set role='branch_officer' where id='<uuid>';
insert into user_branches values ('<uuid>','<branch_id>', true, false); -- แก้ได้ ดูข้อมูลเต็มไม่ได้
```
## หลักการป้องกันข้อมูล
- RLS บังคับทุกตาราง: เห็น/แก้เฉพาะสาขาที่ได้รับมอบหมาย, ไม่มีสิทธิ์ลบ (ใช้สถานะ "พ้นสภาพ")
- เลขบัตรและเลขบัญชีเข้ารหัส (pgcrypto) เก็บแยกตาราง ไม่มี policy อ่านตรง ต้องผ่าน RPC ที่เช็กสิทธิ์รายสาขาและบันทึก `audit_log`
- ตรวจ checksum เลขบัตรประชาชนไทยก่อนบันทึก

## นำเข้า Excel
Admin > เมนู "นำเข้าจาก Excel": เลือกไฟล์ > เลือกชีต+สาขาปลายทาง > ตรวจสอบ > นำเข้า (รันซ้ำได้ ข้ามรหัสที่มีแล้ว)

## ไฟล์แนบ
- พนักงาน: PDF เท่านั้น ประเภท ประวัติพนักงาน/สัญญาจ้าง/เอกสารส่วนตัว/อื่นๆ (ทำเครื่องหมาย "อ่อนไหว" ได้ เห็นเฉพาะผู้มีสิทธิ์ดูเลขเต็ม)
- บริษัท (เมนู "บริษัท"): สัญญาการบริการ/ระเบียบสวัสดิการ/เอกสารอื่นๆ รองรับ PDF, Word, Excel, PNG, JPG ไม่เกิน 20 MB
- ดู/ดาวน์โหลด: ผู้มีสิทธิ์สาขาใดสาขาหนึ่งของบริษัท | แนบ/ลบ: ผู้มีสิทธิ์แก้ไขในสาขานั้น (และ Admin) | ทุกการเปิด/ดาวน์โหลดบันทึกใน Audit Log

## โครงสร้างสาขา/บริษัท (007)
- **สาขา VTA** (service_branches): VTA0001 ลำพูน, VTA0002 บางพลี, VTA0003 พิษณุโลก ... สร้างครั้งเดียว
- **สาขา x บริษัท** (branches): 1 สาขา VTA ดูแลได้หลายบริษัท เลือกบริษัทจากรายการ (ติ๊กในหน้า จัดการระบบ > สาขาและบริษัท) พนักงานสังกัดแถวนี้
- **สิทธิ์ผู้ใช้** ผูกกับสาขา VTA (user_service_branches) ครอบคลุมทุกบริษัทที่สาขานั้นดูแล รวมบริษัทที่เพิ่มภายหลัง
- ตาราง `user_branches` เดิมไม่ถูกใช้แล้ว (เก็บไว้เพื่อย้อนกลับ) ตรวจสิทธิ์ผู้ใช้ทุกคนอีกครั้งหลังรัน 007

## การลาออก (008)
- นำเข้าจากชีต "ลาออก": ตั้งสถานะ "พ้นสภาพ" + เก็บวันที่ลาออก (คอลัมน์ "วันที่ลาออก") + เหตุผลการลาออก (คอลัมน์ "เหตุผลการลาออก") ในทะเบียนพนักงาน
- พนักงานที่นำเข้าไว้แล้วแต่ยังไม่มีเหตุผล: นำเข้าชีตเดิมซ้ำได้ ระบบเติมเฉพาะช่องที่ว่าง ไม่เขียนทับ และไม่แตะพนักงานที่ยังทำงานอยู่
- เปลี่ยนสถานะเป็นพ้นสภาพในฟอร์ม: ต้องกรอกวันที่ลาออก (ใส่วันนี้ให้เป็นค่าเริ่มต้น) / เปลี่ยนกลับเป็นทำงานอยู่: ล้างวันที่-เหตุผล และบันทึกประวัติ "rehire"
- หน้ารายชื่อ: เลือกสถานะ "พ้นสภาพ" จะแสดงคอลัมน์วันที่ลาออกและเหตุผล

## Blacklist (009)
- ตารางแยกจากพนักงาน รับข้อมูลไม่ครบได้ (ไม่มีรหัส/ไม่มีเลขบัตร) เลขบัตรเข้ารหัสและเก็บแฮชไว้เทียบ
- เมนู "Blacklist": ตรวจสอบบุคคล (Admin / ผู้จัดการหลายสาขา / เจ้าหน้าที่สาขา เห็นเฉพาะผลที่ตรงกัน) | รายการทั้งหมด, เพิ่ม/แก้ไข/ถอนออก, ดูเลขบัตรเต็ม, นำเข้าจากชีต backlist (Admin เท่านั้น)
- จับคู่ด้วย: เลขบัตรตรงกัน / รหัสพนักงานตรงกัน / ชื่อ-สกุลตรงกัน (ไม่สนคำนำหน้า) | จับคู่ด้วยชื่ออย่างเดียวจะแสดงคำเตือนว่าอาจเป็นคนละคน
- เพิ่มพนักงานใหม่หรือกรอกเลขบัตร: ระบบเตือนถ้าตรง Blacklist (ไม่ปิดกั้น) | Admin กด "ขึ้น Blacklist" จากหน้าพนักงานได้
- ทุกการตรวจสอบ/ดูเลขเต็ม/แก้ไข บันทึกใน Audit Log (การตรวจสอบบันทึกเฉพาะจำนวนที่พบ ไม่บันทึกข้อมูลที่กรอก)

## ภาพรวม / Dashboard (010)
- เมนู "ภาพรวม" (หน้าแรกหลังเข้าสู่ระบบ): พนักงานทำงานอยู่/ลาพักงาน/รอเริ่มงาน, เข้า-ออก 30 วัน, อัตราลาออก 12 เดือน, อายุงานเฉลี่ย, กำลังคนและเข้า-ออกรายเดือน, แยกตามสาขา VTA / พื้นที่ / บริษัท, เหตุผลลาออก, อายุงาน, ช่วงอายุ, ความครบถ้วนของข้อมูล, ข้อสังเกตและข้อเสนอแนะอัตโนมัติ, ดาวน์โหลด CSV
- คำนวณในฐานข้อมูล (`dashboard_overview`) ส่งกลับเฉพาะตัวเลขรวมตามสาขาที่ผู้ใช้มีสิทธิ์ ไม่มีข้อมูลรายบุคคล กรองตามสาขา VTA / บริษัทได้
- เหตุผลลาออกจัดกลุ่มด้วยคำสำคัญ (ปรับได้ที่ `private.resign_category` ใน 010) เป็นค่าประมาณ | อัตราลาออกขึ้นกับความครบถ้วนของวันที่เริ่มงาน/ลาออก

## การค้นหา (011)
- พนักงาน: ค้นผ่านฟังก์ชัน `search_employees` พิมพ์หลายคำได้ (ชื่อ นามสกุล รหัส ชื่อเล่น ชื่ออังกฤษ) ไม่สนตัวพิมพ์/ช่องว่างแฝง ค้นหาทุกสถานะอัตโนมัติเมื่อมีคำค้น (เลือกสถานะเองเพื่อจำกัดได้) หน่วงการยิงคำค้น 250ms และไม่ให้คำตอบเก่าทับผลล่าสุด
- Blacklist: ค้นด้วยชื่อหรือนามสกุลอย่างเดียว/บางส่วนได้ (ชื่อบางส่วนตั้งแต่ 3 ตัวอักษร) ผลเรียงตรงมากไปน้อย แสดงสูงสุด 50 รายการ
